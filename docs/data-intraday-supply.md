# Сколько новостей реально доступно для внутридневного исследования

**STATUS: BLOCKED по объёму данных, не по коду. Бесплатный путь даёт сотни событий, для
решающей выборки нужно ≥ 2 000 и платный фид.**

Все числа ниже измерены, а не оценены: логи краула `ops/logs/gdelt_pilot2.log`, артефакты
`data/interim/news_raw.parquet` и `data/interim/news_gdelt_pilot.parquet`, кеш
`data/cache/minutes/60m/`. Измерительный скрипт — `ops/audit_measure.py`.

## 1. Пересечения двух бесплатных окон нет

| источник | покрытие | точность метки |
|---|---|---|
| FNSPID (`data/interim/news_raw.parquet`, 124 571 строка) | 2019-01-01 … **2023-12-16 23:02 UTC** | до минуты |
| yfinance 60m бары | **2024-11-11** … сегодня (≈ 499 сессий, глубина 729 дней) | час |

Проверка запросом, а не по документации: строк с `published_at >= 2024-11-11` — **0**; с
`published_at >= 2024-01-01` — **0**. Разрыв между концом новостей и началом баров — **11 месяцев**.
Единственный источник с минутными метками и без ключа, покрывающий 2024-11 … 2026-11, — GDELT
DOC 2.0.

## 2. Измеренный throughput GDELT

Один прогон: 5 тикеров, окно 2026-10-01 … 2026-11-01, `--pause 20`.

| метрика | значение |
|---|---|
| запросов | 10 |
| из них HTTP 429 после 5 попыток | **2 (20 %)** |
| слайсов упёрлись в лимит 250 записей | **3 (30 %)** |
| сырых статей | 750 |
| отброшено как `no_alias` | **634 (84.5 %)** |
| `ambiguous_alias` | 6 |
| дубликатов URL | 4 |
| пустых заголовков | 1 |
| **оставлено статей** | **105 (14.0 % от сырых)** |
| wall clock | 18:01:16 → 18:22:05 = **20 мин 49 с** |
| среднее на запрос | **125 с** (успешный ≈ 66 с, отказавший ≈ 6 мин backoff) |

Три структурных ограничения, каждое видно в этой таблице:

1. **84.5 % отсева по атрибуции.** GDELT ищет по полному тексту, а тикер присваивается только по
   заголовку. Обзор рынка, где Apple упомянута в третьем абзаце, приходит как хит и умирает как
   `no_alias`. Это не лечится краулом: доля одинакова в каждом окне.
2. **Лимит 250 записей на слайс.** 3 из 10 слайсов упёрлись в потолок, то есть обрезаны **именно
   самые насыщенные новостями тикеро-месяцы** — те, где живут события. Пропуск не случайный: он
   коррелирован с объёмом новостей, а значит смещает выборку в сторону тихих дней.
3. **20 % отказов при темпе 1 запрос в 2 минуты.** 429 — это лимит по IP, и он не станет мягче при
   крауле на 300 запросов. Измеренная доля отказов — нижняя граница, а не средняя.

## 3. Экстраполяция до 2 000 событий

Измеренные конверсии: 10.5 статьи на запрос; 105 статей → **59 событий** (56 %: 24 без баров,
14 после закрытия, 8 дублей). Значит 2 000 событий требуют ≈ 3 570 статей ≈ **340 запросов**.

| сценарий | запросов | wall clock (успех 66 с) | с 20 % отказов |
|---|---|---|---|
| 40 тикеров × 3 месяца, месячные слайсы | 120–240 | 2.2–4.4 ч | 3–6 ч |
| 40 тикеров × 3 месяца, недельные слайсы (против saturation) | 480 | **8.8 ч** | **14–20 ч** |
| 40 тикеров × 12 месяцев, недельные слайсы | 1 920 | 35 ч | 56–80 ч |

Режимы отказа, которые нельзя устранить настройкой: 429-шторм при длинном крауле; обрезание
самых плотных окон лимитом 250; 84.5 % потерь на атрибуции; тикеры без часовой истории в
yfinance (в пилоте 24 из 105 статей умерли именно так); и главное — **отсутствие данных за 2024-11
… 2026-09**, если не краулить два года, что упирается в строку «1 920 запросов».

## 4. Платные фиды: что проверено, а что нет

Попытка извлечь лимиты со страниц документации вернула только обрывки токенов (`"1"`, `"5"`,
`"25"`) — страницы рендерятся JavaScript, цитируемых предложений получить не удалось. Публиковать
числа из такого извлечения нельзя, поэтому таблица ниже **не содержит ни одного непроверенного
лимита**:

| вендор | документация | free tier | глубина истории | точность метки |
|---|---|---|---|---|
| Finnhub | finnhub.io/docs/api/company-news | UNVERIFIED | UNVERIFIED | UNVERIFIED |
| Alpha Vantage (`NEWS_SENTIMENT`) | alphavantage.co/documentation | UNVERIFIED | UNVERIFIED | UNVERIFIED |
| Marketaux | marketaux.com/documentation | UNVERIFIED | UNVERIFIED | UNVERIFIED |
| Tiingo | tiingo.com/documentation/news | UNVERIFIED | UNVERIFIED | UNVERIFIED |
| EODHD | eodhd.com/financial-apis/stock-market-financial-news-api | UNVERIFIED | UNVERIFIED | UNVERIFIED |
| Polygon | polygon.io/docs/stocks/get_v2_reference_news | UNVERIFIED | UNVERIFIED | UNVERIFIED |
| Alpaca | docs.alpaca.markets/reference/news-3 | UNVERIFIED | UNVERIFIED | UNVERIFIED |

Проверено только одно: **ни одного ключа этих вендоров нет в окружении** (Alpaca, Polygon,
Finnhub, Tiingo, AlphaVantage, EODHD — отсутствуют). Поэтому вопрос «сколько стоит решающая
выборка» остаётся открытым, а не решённым в пользу бесплатного пути.

## 5. Минимальный план, дающий ≥ 2 000 событий

Цель — MDE ≈ 8 бп при σ ≈ 65 бп (`MDE = 2.802 · σ / √n`, n = 2000 → 4.1 бп без inflation, 8 бп с
двукратным запасом на кластеризацию).

1. **Новости.** 40 тикеров, окно 2025-01-01 … 2026-11-08, недельные слайсы (защита от лимита 250),
   `--pause 20`, 4 потока запрещены. Ожидание: 40 × 96 недель = 3 840 запросов, 6–8 суток
   непрерывной работы, 20–40 % отказов. Это делает краул фоновым процессом на неделю, а не задачей
   на вечер.
2. **Бары.** 60m из yfinance, глубина 729 дней — окно 2024-11-11 … 2026-11-08 покрывается целиком;
   для 2025-01 начала не хватает, поэтому либо окно с 2024-11-11, либо 30m (59 дней) как отдельный
   тест чувствительности.
3. **Разметка.** FinBERT локально, 3 840 × 10 запросов ≈ 40 тыс. заголовков, ≈ 1 ч на GPU.
4. **Ожидаемая конверсия.** 340 запросов → 3 570 статей → 2 000 событий. При 20 % отказов —
   2 700 статей → 1 500 событий. Нижняя реалистичная оценка: **1 400–2 000 событий**, MDE 9–11 бп.

Режимы отказа плана: 429-шторм делает недельный график непредсказуемым; saturation продолжает
обрезать плотные недели; 84.5 % потерь на атрибуции не меняются; делистинг и смена тикеров за два
года не моделируются.

**Альтернатива, которая решает вопрос за час:** платный фид с минутными метками и историей ≥ 2
лет. Без него потолок бесплатного пути — примерно **1 400–2 000 событий при неделях ожидания**, и
это всё равно меньше, чем нужно для эффекта 8 бп с запасом.

## 6. Что нельзя утверждать

1. «Новостей мало» — их много (750 сырых за 10 запросов), но 84.5 % не атрибутируются по заголовку.
2. «GDELT медленный» как причина — медленность это 429, а не сам API: успешный запрос — 66 с.
3. Любые числа из таблицы платных фидов — они помечены UNVERIFIED именно потому, что не проверены.
4. «Пилот что-то доказал» — 59 событий на 6 сессиях дают MDE 22 бп, а правдоподобный эффект 8–10 бп.
