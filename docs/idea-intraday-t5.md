# Идея следующего шага: реакция через 5 минут после выхода статьи

Дневной горизонт провалил собственный гейт (`results/test_2023.json`: IC 0.0127, CI содержит ноль)
и экономику (net Sharpe −6.75 при обороте 166×/год). Но провал дневного горизонта не говорит, что
новостного сигнала нет вообще — он говорит, что сигнал **либо слишком мал, либо уже съеден к
закрытию сессии**. Проверить второе можно только на внутридневных данных.

Ниже — конструкция, которая не переиспользует ни одну дневную метку и поэтому не наследует ни один
из дефектов дневного датасета.

## Что именно меняется

| | дневной подход (текущий) | внутридневной подход |
|---|---|---|
| событие | `(ticker, signal_date)` — агрегат за день | `(article_id, ticker, published_at)` — одна статья |
| вход | следующий открытие | первый минутный бар с `start ≥ published_at + 5 мин` |
| выход | закрытие следующей сессии | закрытие той же сессии (база) или `entry + 60 мин` |
| цель | `log(adj_close[t+1]/adj_close[t])` | `excess_ret` события, см. ниже |
| кросс-валидация | по датам панели | по датам событий, эмбарго 1 день |

## Определения

```
entry_ts  = min{ bar.start : bar.start >= published_at + 5min, bar ∈ [09:30, 16:00) ET }
exit_ts   = последний бар сессии (09:30–16:00 ET)
r_event   = adj_close(exit_ts) / open(entry_ts) - 1
r_spy     = spy(exit_ts) / spy(entry_ts) - 1
y         = r_event - r_spy                     # excess return, вход и выход в одни и те же минуты
```

Требования: `published_at` с точностью до минуты, бары с точностью до минуты, обе серии
синхронизированы по календарю NYSE. Событие отбрасывается, если `entry_ts` попадает в последние
30 минут сессии (выход слишком короткий) или если в окне нет баров.

## Почему это снимает ошибки датасета

1. **Один timestamp вместо политики дня.** Дневной пайплайн выводил `signal_date` из `published_at`,
   cutoff 16:00 ET и торгового календаря — три места, где можно ошибиться, и именно там нашлись
   дефекты (`strict_dates` сдвигал всего 10 строк из 124 571). Здесь событие — само `published_at`,
   без политики.
2. **Нет агрегации.** Медиана корпуса — 1 статья на тикер-день, максимум 19; дневные `sent_mean` и
   `pos_share` смешивают разные события. Событийная постановка сохраняет статью как единицу
   наблюдения и позволяет взвешивать по уверенности модели, а не по среднему.
3. **Нет утечки через `adj_close[t+1]`.** Дневная цель требовала лага в целую сессию; здесь вход и
   выход внутри одной сессии, и обе цены берутся из баров, а не из скорректированных закрытий,
   которые пересчитываются задним числом при сплитах.
4. **Лаг фиксирован и наблюдаем.** Ровно 5 минут — это проверяемое правило, а не эвристика
   «новость после закрытия считается следующей сессией». Если эффект есть только на 30-й минуте,
   это видно по сетке лагов (5/15/30/60), а не теряется в дневном агрегате.
5. **Дубли видны по таймстемпу.** Перепечатка одной новости десятью изданиями в дневном агрегате
   превращается в «сильный сентимент дня». В событийной постановке дубли склеиваются по
   `(title_hash, 6-часовое окно)` и остаётся первое издание.
6. **Издержки считаются на реальном обороте.** Дневной тест показал 166×/год — при событийной
   постановке оборот задаётся числом событий, и его можно ограничить отбором top-k по уверенности.

## Признаки события

| группа | признаки |
|---|---|
| сентимент | `p_pos`, `p_neg`, `score_5`, `confidence`, `is_novel`, `is_company_specific` |
| текст | длина заголовка, число цифр/процентов, наличие «beats/misses/upgrade/downgrade/recall/lawsuit» |
| время | минута публикации, до/после открытия, день недели |
| контекст | `vol_20` **строго до даты события** (не включая её), `ret_1` до события, импульс SPY за 30 минут до входа |
| ликвидность | оборот бумаги за предыдущую сессию, спред из баров (если есть bid/ask) |

Целевой признак — `y` выше; модель — либо LightGBM на событиях, либо простое правило
«шорт верхнего квинтиля негатива / лонг нижнего» для базовой линии.

## Минутные данные

| источник | покрытие | стоимость | оговорка |
|---|---|---|---|
| Alpaca IEX | 2016 → сейчас, только IEX-объём | бесплатно с ключом | IEX — ~2% рынка, бары разрежены, ликвидность искажена |
| Polygon.io | 2003 → сейчас, консолидированные | платно | лучший вариант для 2019–2021 |
| yfinance (1m) | последние 30 дней | бесплатно | только forward-тест, без истории |

Для ретроспективной части 2019–2021 нужен Polygon или другой консолидированный источник; IEX
годится для forward-теста. Без минутных баров идею проверить нельзя — это первый блокер, и он
покупается, а не пишется.

## Валидация

* purged CV по датам событий: фолды по месяцам, эмбарго 1 торговый день между train и test;
* метрики: hit rate (доля событий с правильным знаком), IC по событиям внутри даты, средний
  спред между квинтилями уверенности, t-статистика по кластеризованным по дате ошибкам;
* издержки: 5+5 б.п. на сторону плюс половина спреда из баров; отбор top-k событий в день
  (k = 5, 10, 20), чтобы оборот был управляемым;
* обязательный контроль: те же события, но вход через 30 и 60 минут — если эффект исчезает к 30-й
  минуте, это результат про скорость реакции, а не про сентимент.

## Что уже готово и что нужно

Готово: сентимент-бэкенды (FinBERT, lexicon, open-jev), дедуп по заголовку и URL, событийная
таблица `article_id/ticker/published_at` из корпуса, калибровка уверенности.

Нужно: минутные бары (внешний источник), модуль `src/spp/live/minutes.py` (загрузка и выравнивание
баров), `src/spp/live/events.py` (построение `entry_ts`/`exit_ts`, расчёт `y`), `configs/intraday.yaml`,
`tests/test_intraday_events.py`, базовый отчёт `reports/intraday_baseline.md`.

## Риск, который надо принять заранее

Если рынок эффективен на пятиминутном горизонте, эффект будет нулевым — и это тоже результат:
он означает, что дневной провал объясняется не грубостью агрегации, а отсутствием предсказуемости
в новости вообще. Отрицательный ответ здесь стоит дешевле, чем ещё один год дневных аблаций.
